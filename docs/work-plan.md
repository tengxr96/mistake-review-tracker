# Individual Work Plan

## Responsibilities

I will handle requirements, design, Java development, verification, documentation, and repository maintenance. My available time is approximately two hours per week.

The initial version will be a Java Swing desktop application with local storage. Accounts, cloud synchronization, OCR, AI answers, and scheduled reminders are outside its scope.

## Working Agreement

I will create issues for substantial tasks, make meaningful commits, and review progress weekly. Self-reviews and unfinished work will be clearly identified.

## Tentative Milestones

Weeks 1 and 2: Learn basic Swing and build a prototype that imports, displays, saves, and reopens one screenshot record.

Weeks 3 and 4: Add course and topic details, error explanations, and saved understanding statuses.

Week 5: Add filtering by course, topic, and status, including empty results.

Week 6: Check acceptance criteria, fix problems, and update documentation and known limitations.

This is a provisional 12-hour budget after P1, subject to course deadlines. I will revise it after the first prototype if the work takes longer than expected.

## Risks

GUI development is new to me, so I will keep the interface simple and evaluate feasibility early. To reduce data-loss risk, I will check that screenshots and records reopen correctly. Consistent topic names will help filtering. Optional enhancements will be deferred if time is limited; changes to required scope will be documented.

## Repository and Evidence

README.md introduces the project. The docs folder contains the proposal, requirements, use cases, and work plan. Source code will be added separately when development starts.

My contribution statement will link to actual issues, commits, and self-reviews. Planned work will be distinguished from completed work, and verification results will be reported only after the checks are performed.
